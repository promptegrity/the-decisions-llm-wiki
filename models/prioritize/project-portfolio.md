# Overview

A Project Portfolio is a single view of everything you are running, paused, or considering — not a to-do list of tasks, but a map of **initiatives**. The point is to see load, overlap, and neglect at a glance so you stop managing only whatever is loudest this week.

Without a portfolio, “busy” hides imbalance: three half-finished projects and no capacity for the one that matters.

### Diagram

```text
  [P1] status · next · owner
  [P2] status · next · owner
  [P3] ...
  ---------------- capacity line ----------------
  (pause / kill / merge what sits above the line)
```

# When to use

- You have more than a handful of parallel projects (work, side, personal, learning).
- Deadlines collide and you cannot tell what is active vs zombie.
- You are about to start something new and need to know what it displaces.
- Status updates feel scattered across notes, chats, and memory.

Skip it when the problem is sorting today’s tasks (use [Eisenhower Matrix](/models/prioritize/eisenhower-matrix.md)), when you need cost–benefit ranking (use [BCG Matrix](/models/prioritize/bcg-matrix.md)), or when you are stuck choosing one goal (use [SMART Model](/models/prioritize/smart-model.md) first).

# How it works

List every project as a row (or card). Keep fields few and honest:

| Project | Status | Next milestone | Capacity this week | Owner / dependency | Park / kill? |
|---------|--------|----------------|--------------------|--------------------|--------------|
| … | Active / Paused / Idea | … | High / Med / Low | … | Yes / No |

### Steps

1. **Inventory** — dump everything that claims to be a “project” (including lingering ideas).
2. **Status** — Active (work happening), Paused (explicit hold), Idea (not started), Done/Archive.
3. **Next milestone** — one concrete next outcome, not a vague hope.
4. **Capacity** — rough share of your week; if totals exceed 100%, something must move.
5. **Decide** — start / continue / pause / kill; write the decision on the row so zombies do not return quietly.

### Simple visual (optional)

Group projects into lanes: **Now** (few), **Next**, **Later**, **Parking lot**. Cap “Now” hard — usually 1–3 for deep work.

### Practice tip

Review the portfolio on a fixed cadence (e.g. weekly 15 minutes). The value is the **overview ritual**, not a perfect spreadsheet. If a project has no next milestone for two reviews, it is paused or dead — name it.

### Facilitation steps

1. **Inventory** — List every active project or major initiative (including “shadow” ones).
2. **Status** — For each: goal in one line, status, next milestone, owner (you/other).
3. **Gaps** — What important work is invisible or has no next step?
4. **Load** — Which projects should pause, kill, or merge so the portfolio fits real capacity?
5. **Review** — When is the next portfolio review, and what will you check then?
