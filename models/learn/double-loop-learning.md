# Overview

**Double-loop learning** (Chris Argyris / Donald Schön) distinguishes fixing actions inside existing rules from **revising the rules themselves**. Single-loop: detect error → adjust behavior. Double-loop: detect error → ask *why those goals, norms, and assumptions?* → change the governing variables.

The point: many “lessons learned” only optimize a broken frame.

### Diagram

```text
  Single loop:  action → result → change tactics → action
  Double loop:  action → result → question governing assumptions → new action
```

# When to use

- The same failure repeats after “process tweaks.”
- Postmortems list actions but never touch incentives, identity, or sacred metrics.
- A team is defensive: data threatens self-image, so learning stays cosmetic.
- You need to understand why smart people keep defending a failing strategy.

Skip it when you mainly need appreciative energy and strengths (use [Appreciative Inquiry](/models/relate/appreciative-inquiry.md)) or a personal feedback habit (use [Feedback Analysis](/models/learn/feedback-analysis.md)).

# How it works

### Single loop vs double loop

```
Governing variables (goals, values, assumptions)
 ↓
 Action strategies
 ↓
 Consequences
 ↑
 (single loop: adjust actions)
 (double loop: also revise governing variables)
```

| Loop | Question | Risk if you stop here |
|------|----------|------------------------|
| **Single** | “How do we do this better next time?” | Efficient at the wrong thing |
| **Double** | “Should we still be trying to do *this*?” | Slower, but can stop systemic waste |

### Typical blockers (Model I)

Argyris describes defensive routines: win/don’t lose, suppress negative feelings, appear rational. Those routines **prevent** double-loop talk — especially when status is at stake.

### Questions for a real lesson

1. What **assumption** made this action seem right?
2. What **metric or identity** are we protecting?
3. If that assumption were false, what would we do differently?
4. What would we need to **unlearn** — not just add?

### How to act

1. Separate **error detection** from **blame** so people can surface assumptions.
2. Write the **governing variables** explicitly (goals, constraints, “we never…”).
3. Run a double-loop review: which variables still hold after the evidence?
4. Redesign incentives and language so the new frame can survive Monday morning.

### Practice tip

After any significant miss, require one slide titled “Assumptions we will retire.” If the room can’t name any, you are still in single-loop.

### Facilitation steps

1. **Episode** — Describe a mistake or failed attempt in one paragraph.
2. **Single loop** — What tactic would you change if you only fixed “how we did it”?
3. **Governing assumption** — What deeper rule/goal/belief drove that approach?
4. **Double loop** — If that assumption were wrong, what new governing idea fits better?
5. **Act** — What will you do differently next time *because* of the new assumption?
