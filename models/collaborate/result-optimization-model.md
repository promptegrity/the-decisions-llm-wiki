# Overview

The Result Optimization Model treats progress as something you **accumulate**, not something you wait to feel. Instead of only fixing failures, you deliberately create a chain of **small, attributable successes** — then use that evidence to raise standards, confidence, and ambition. Momentum becomes a management tool: people (and teams) improve faster when wins are noticed, sequenced, and compounded.

The opposite habit — endless gap analysis without wins — drains energy and makes “improvement” feel like permanent deficit.

### Diagram

```text
  small win → make visible → reinforce → next win (stack)
```

# When to use

- A team or person is stuck in problem-focus and low confidence.
- You need early traction on a new initiative or turnaround.
- Successes happen but vanish unmarked, so nothing compounds.
- You want to raise performance without only adding pressure.

Skip it when you must first cut scope honestly (use [Project Management Triangle](/models/prioritize/project-management-triangle.md)) or when the goal itself is wrong (use [SMART](/models/prioritize/smart-model.md)).

# How it works

Optimize for a **portfolio of wins**: frequent enough to build belief, meaningful enough to matter, visible enough to be shared.

### Loop

1. **Define a win** — small, observable outcome (not effort): shipped, decided, learned, closed.
2. **Sequence** — order wins so each one unlocks or advertises the next.
3. **Attribute** — make clear who/what caused the result (so success is teachable).
4. **Reinforce** — celebrate and document; turn the win into a standard or playbook.
5. **Raise the bar** — only after a streak exists; stretch from strength, not from shame.

### Questions

1. What is the smallest success we can land this week that others can *see*?
2. Which existing strength, if repeated, would create the next win cheapest?
3. Which “improvements” are actually unscoped perfectionism that block accumulation?
4. Have we recorded last month’s wins well enough that a newcomer could reuse them?

### How to act

1. **Prefer strength-building over weakness-chasing** when both are optional.
2. **Publicize wins proportionally** — enough to create learning, not theater.
3. **Batch lessons** from successes the way you already batch post-mortems from failures.
4. **Stop collecting hollow metrics**; only count results that change behavior or capability.

### Practice tip

Keep a shared “success log” next to the issue tracker. Review it in the same ritual as blockers. Optimization starts when wins get equal airtime.

### Facilitation steps

1. **Win** — What small, visible success can we aim for next?
2. **Stack** — What already works that we can reinforce?
3. **Sequence** — How do early wins unlock the next?
4. **Noise** — What big redesign will we *not* do until wins stack?
5. **Celebrate** — How will the win be made visible to the team?
